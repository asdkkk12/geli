本次部署分成三部分：**通过 geli 创建应用容器 → 在宿主机准备数据库和代码 → 在容器中启动应用**。

当前已经部署成功，访问 http://127.0.0.1:53750 即可。下面是从零开始的人工操作流程；如果只是体验现有实例，直接看第 6 步。

## 1. 启动 geli 平台

操作位置：**Mac 终端**。

```
cd /Users/yuanyaowu/Desktop/geli
npm run demo
```

看到“演示启动成功”后，打开：

```
http://127.0.0.1:5173
```

## 2. 通过 geli 申请应用容器

操作位置：**geli 网页**。

使用普通用户登录，进入“申请容器”，填写：

| 字段     | 填写内容         |
| -------- | ---------------- |
| 名称     | `example-login`  |
| 用途     | 部署登录示例     |
| 镜像模板 | `lab-dev`        |
| CPU      | `1`              |
| 内存     | `1024` MB        |
| 磁盘     | `2` GB           |
| 运行时长 | 根据演示需要填写 |
| 应用端口 | `8080`           |

然后：

1. 点击“提交审批”。
2. 使用管理员登录 geli。
3. 在“申请记录”中找到 `example-login`。
4. 点击“通过并创建”。
5. 等待状态变成 `RUNNING`。

这里创建的是应用容器；PostgreSQL 数据库将在后续步骤单独创建。

下面的命令使用本次实际容器名；重新部署到其他容器时需要替换。

## 4. 准备独立数据库、网络和源码

操作位置：**Mac 终端**，不是网页容器终端。

### 4.1 进入示例目录

```
cd /Users/yuanyaowu/Desktop/geli
export PATH="$PWD/node_modules/node/bin:$PATH"
node --version
```

应输出 Node.js `v22…`。

然后：

```
cd exampleProject
npm ci
npm run build
```

### 4.2 执行部署前检查

```
npm run deploy -- lab-4d61ae51-7bd1-4105-ba1d-63680a5cabe9 --check
```

它只检查目标，不执行部署，主要确认：

- 是 geli 创建的运行中容器。
- 容器内部端口 `8080` 已映射到本机。
- `8080` 没有被另一个应用占用。
- 目标目录和已有数据库资源属于本示例。

**当前应用已经运行，因此现在再次执行检查，会提示 `8080` 已占用。这是预期保护，不代表部署失败。**

### 4.3 设置独立数据库密码

首次部署时，准备一个 **20～128 位、只包含字母、数字、下划线或连字符**的密码，并保存好。

在 Mac 默认 zsh 终端执行：

```
read -s 'EXAMPLE_DB_PASSWORD?独立数据库密码：'
echo
export EXAMPLE_DB_PASSWORD
```

在提示后输入密码并回车，输入过程不回显。

**本次数据库已经创建，重复部署必须使用原密码。** 原密码位于：

[exampleProject/.runtime/local-demo.json](/Users/yuanyaowu/Desktop/geli/exampleProject/.runtime/local-demo.json)

其中：

- `databasePassword`：数据库密码。
- `password`：示例网页登录密码。

两者不要混淆。

### 4.4 执行部署

首次部署或停止现有示例后执行：

```
npm run deploy -- lab-4d61ae51-7bd1-4105-ba1d-63680a5cabe9
unset EXAMPLE_DB_PASSWORD
```

脚本自动完成：

1. 创建独立 PostgreSQL 容器。

2. 创建普通持久化数据卷，保存数据库数据。

3. 创建专用内部网络。

4. 将 PostgreSQL 和应用容器连接到该网络。

5. 为数据库设置网络别名 `example-db`。

6. 将源码放到应用容器的：

   ```
   /home/developer/exampleProject
   ```

7. 以 UID `1000` 解包文件，保证容器普通用户能够读写。

8. 打印应用实际访问地址。

本次数据库资源为：

```
数据库容器：geli-example-599655265d-postgres
数据库卷：  geli-example-599655265d-data
专用网络：  geli-example-599655265d-network
```

数据库没有发布宿主机端口，应用通过专用网络连接它。

## 5. 在 geli Web Terminal 中启动应用

操作位置：**geli 网页 → 我的容器 → example-login → 进入终端**。

### 5.1 安装依赖并构建

```
cd /home/developer/exampleProject
npm ci
npm run build
```

这一步在容器的 Linux 环境中安装依赖，不能直接复用 Mac 的 `node_modules`。

### 5.2 设置浏览器访问地址

使用第 3 步查到的实际端口：

```
export PUBLIC_ORIGIN='http://127.0.0.1:53750'
```

必须与浏览器打开的地址完全一致：

- 不要额外添加末尾 `/`。
- 不要一边配置 `127.0.0.1`，一边用 `localhost` 访问。

### 5.3 设置数据库连接

执行：

```
printf '数据库密码：'
stty -echo
IFS= read -r EXAMPLE_DB_PASSWORD
stty echo
printf '\n'
```

输入第 4 步设置的数据库密码并回车，然后执行：

```
export DATABASE_URL="postgresql://example_user:$EXAMPLE_DB_PASSWORD@example-db:5432/example_project"
unset EXAMPLE_DB_PASSWORD
```

连接信息分别是：

| 项目       | 值                |
| ---------- | ----------------- |
| 数据库地址 | `example-db`      |
| 数据库端口 | `5432`            |
| 数据库名称 | `example_project` |
| 数据库用户 | `example_user`    |

如果隐藏输入被中断，导致终端不显示输入内容，执行：

```
stty echo
```

### 5.4 创建示例登录账号

```
npm run init-user
```

根据提示输入：

1. 用户名，例如 `demo`。
2. 登录密码，至少 12 个字符。

这是**示例应用的账号**，不是 geli 平台账号，也不是 PostgreSQL 账号。

如果用户名已经存在，初始化命令会保留原密码，不会重置。

### 5.5 启动应用

```
npm start
```

看到：

```
Example 服务启动，端口 8080
```

说明应用已经启动。保持终端运行，`Ctrl+C` 会停止前台服务。

**当前实例已经在后台运行，不要直接再次执行 `npm start`，否则会出现端口占用。**

## 7. 改为后台运行

操作位置：**geli Web Terminal**。

如果当前是前台运行，先按 `Ctrl+C`。保持数据库连接和 `PUBLIC_ORIGIN` 环境变量仍然存在，再执行：

```
mkdir -p .runtime
nohup node dist/server/main.js > .runtime/app.log 2>&1 < /dev/null &
echo $! > .runtime/app.pid
```

查看日志：

```
tail -n 50 .runtime/app.log
```

持续查看日志：

```
tail -f .runtime/app.log
```

此时按 `Ctrl+C` 只会停止日志跟踪，不会停止后台应用。

geli 页面上的“日志”显示容器主进程日志，不会自动显示这里的 `app.log`。

## 8. 停止和重新启动应用

操作位置：**geli Web Terminal**。

先进入目录并核对进程：

```
cd /home/developer/exampleProject
ps -p "$(cat .runtime/app.pid)" -o pid,args
```

确认显示的是本例的：

```
node dist/server/main.js
```

再执行：

```
kill -TERM "$(cat .runtime/app.pid)"
```

重新启动时，可以重新设置第 5 步的环境变量，再执行：

```
npm start
```

本次已经准备了宿主机快捷启动脚本。**应用停止且容器内构建完成后**，也可以在 Mac 终端执行：

```
cd /Users/yuanyaowu/Desktop/geli/exampleProject
node scripts/start-local-demo.cjs lab-4d61ae51-7bd1-4105-ba1d-63680a5cabe9
```

它读取本例数据库凭据、复用本地演示账号并后台启动应用。账号密码保存到 `.runtime/local-demo.json`，不会修改 geli 的账号。

## 10. 容器停止后，哪些步骤需要重做

| 情况                      | 处理方式                                                     |
| ------------------------- | ------------------------------------------------------------ |
| 只停止示例 Node 进程      | 重新启动应用即可                                             |
| 关闭 Web Terminal         | 前台进程可能结束；后台运行方式更适合保持服务                 |
| geli 用户容器停止后再启动 | 检查源码是否仍在，重新设置环境并启动应用                     |
| 用户容器工作目录丢失      | 重新执行宿主机部署、容器安装与构建                           |
| 重新创建用户容器          | 使用新 UUID、新映射端口，重新连接部署；旧网络连接需管理员核查 |
| PostgreSQL 停止后再启动   | 普通持久化卷保留数据库数据，继续使用原密码                   |

这里最关键的是：**本机用户工作目录是 `tmpfs`，可能随停止/卸载丢失；独立 PostgreSQL 使用普通持久化卷。** 因此源码以 Mac 上的 `exampleProject/` 为准，数据库数据单独保留。
