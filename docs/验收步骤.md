# 平台验收步骤

本文用于验收本项目本机演示中的用户容器、开发环境和基础隔离能力。

## 1. 验收前提

1. Docker Desktop 已启动并执行 `npm run demo`。
2. 浏览器访问 `http://127.0.0.1:5173`。
3. 已创建普通用户，并使用普通用户登录。
4. 普通用户已申请容器，管理员已审批并创建容器。
5. 容器状态为 `RUNNING`，并已点击“进入终端”。

本机演示中，容器终端的默认工作目录为 `/home/developer`。

## 2. 权限和身份验收

在容器终端执行：

```bash
id
whoami
pwd
ls -la
```

预期结果：当前用户不是 `root`，通常为 `developer`，UID/GID 为 `1000`，当前目录为 `/home/developer`，并且能够读写自己的工作目录。

## 3. 开发环境验收

### 3.1 工具版本

```bash
node --version
npm --version
python3 --version
java -version
git --version
ps
top
```

预期结果：Node.js、npm、Python、Java、Git、`ps` 和 `top` 均能正常执行。

### 3.2 Git 操作

需要容器能够访问互联网时执行：

```bash
cd ~
git clone https://github.com/octocat/Hello-World.git git-test
ls -la git-test
rm -rf git-test
```

预期结果：仓库能够克隆并查看文件。若因网络或代理失败，应先检查容器网络，不要直接判定镜像功能失败。

### 3.3 npm 依赖安装

```bash
mkdir -p ~/acceptance-test
cd ~/acceptance-test
npm init -y
npm install lodash
node -e "console.log(require('lodash').VERSION)"
```

预期结果：`npm install` 成功，并输出 lodash 版本号。

### 3.4 Python 依赖安装

```bash
cd ~/acceptance-test
python3 -m venv .venv
. .venv/bin/activate
pip install requests
python -c "import requests; print(requests.__version__)"
deactivate
```

预期结果：虚拟环境创建成功，`requests` 安装成功并能被 Python 导入。

## 4. 程序构建和运行验收

### 4.1 Node.js 构建

```bash
cd ~/acceptance-test
printf '{"scripts":{"build":"node -e \"console.log(\\\"build ok\\\")\"}}' > package.json
npm run build
```

预期输出包含 `build ok`。

### 4.2 Python 程序

```bash
cd ~/acceptance-test
printf 'print("python ok")\n' > app.py
python3 app.py
```

预期输出：`python ok`。

### 4.3 Java 程序

```bash
cd ~/acceptance-test
printf 'public class Main { public static void main(String[] args) { System.out.println("java ok"); } }' > Main.java
javac Main.java
java Main
```

预期输出：`java ok`。

## 5. 进程隔离验收

```bash
ps -ef
echo $$
```

预期结果：只能看到当前容器内的进程，看不到宿主机和其他用户容器的进程。不要仅根据 PID 数值判断隔离，应以进程列表内容为准。

## 6. Docker 管理权限隔离验收

```bash
command -v docker || echo "PASS: docker command unavailable"
test ! -e /var/run/docker.sock && echo "PASS: Docker Socket unavailable"
```

预期输出：

```text
PASS: docker command unavailable
PASS: Docker Socket unavailable
```

如果系统中存在 Docker 命令，再执行：

```bash
docker ps
```

预期应当失败。普通用户容器不能查看或管理宿主机 Docker。

## 7. 容器文件隔离验收

在第一个用户容器中执行：

```bash
echo "container-a-secret" > ~/isolation-test.txt
cat ~/isolation-test.txt
```

使用另一个用户进入另一个容器，在第二个容器中执行：

```bash
test ! -e /home/developer/isolation-test.txt && echo "PASS: containers are isolated"
```

预期输出：`PASS: containers are isolated`。测试完成后回到第一个容器删除文件：

```bash
rm -f ~/isolation-test.txt
```

## 8. 资源限制验收

```bash
nproc
free -m
cat /sys/fs/cgroup/cpu.max 2>/dev/null || true
cat /sys/fs/cgroup/memory.max 2>/dev/null || true
```

预期结果：容器能够看到平台申请的 CPU 和内存限制，而不是无限使用宿主机资源。不要在生产环境中使用高负载压力测试。

## 9. 平台流程验收

1. 管理员在“创建账号”中创建普通用户。
2. 普通用户登录并提交容器申请。
3. 管理员或审批人在“申请记录”中点击“通过并创建”。
4. 等待容器状态变为 `RUNNING`。
5. 普通用户点击“进入终端”，执行本文第 2～8 节命令。
6. 在容器页面测试停止、启动、重启和日志查看。
7. 使用“删除容器”结束测试。

## 10. 不能只通过容器终端验证的项目

以下项目需要结合管理员界面、Docker Desktop、API/Agent 日志或集成测试验证：

- 普通用户不能登录宿主机或执行宿主机命令。
- 普通用户不能管理其他用户容器。
- 资源超限时平台拒绝创建或限制运行。
- 高风险容器配置被系统拒绝。
- 容器删除后数据卷是否按策略保留。
- Agent 与 API 之间的签名认证和生产 TLS 配置。
