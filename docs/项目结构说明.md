# 项目结构说明

本文说明 `geli` 实验室 Docker 容器平台的目录结构、主要文件职责和运行关系。

## 1. 项目概览

项目采用 npm workspaces 管理三个应用：

| 模块 | 技术栈 | 主要职责 |
| --- | --- | --- |
| `apps/web` | Vue 3、Vite、TypeScript | 浏览器界面、登录、容器申请、审批和 Web Terminal |
| `apps/api` | NestJS、TypeScript、PostgreSQL、Redis、BullMQ | 用户认证、业务接口、审批、任务队列和 Agent 调度 |
| `apps/agent` | NestJS、TypeScript、Dockerode | 在 Docker 节点上创建、管理和监控用户容器 |

总体调用关系：

```text
浏览器
  │
  ▼
apps/web  ── HTTP/WebSocket ──>  apps/api
                                  │
                                  ├── PostgreSQL：业务数据
                                  ├── Redis：会话、队列和节点状态
                                  └── apps/agent：签名请求
                                         │
                                         └── Docker Engine：用户容器
```

## 2. 根目录

```text
geli/
├── apps/                         三个应用模块
├── deploy/                       部署配置和开发镜像
├── docs/                         使用、部署和验证文档
├── scripts/                      本机演示和集成测试脚本
├── .env.example                  环境变量示例
├── .gitignore                    Git 忽略规则
├── docker-compose.yml             本地基础设施示例配置
├── package.json                  根 workspace 和统一脚本
├── package-lock.json              锁定依赖版本
├── README.md                     项目快速说明
├── PLAN.md                       实施方案和架构设计
└── 需求文档.md                   产品需求和验收标准
```

以下目录不属于源码说明范围：

- `node_modules/` 和各 workspace 下的 `node_modules/`：npm 依赖安装目录。
- `apps/*/dist/`、`apps/web/dist/`：TypeScript/Vite 构建产物，可重新生成。
- `.demo/`：本机演示运行时日志和状态文件，已加入 Git 忽略。

## 3. 根目录配置和脚本

### `package.json`

定义 npm workspaces 和统一命令：

```bash
npm run build       # 构建 API、Agent 和 Web
npm test            # 运行测试
npm run demo        # 启动本机演示
npm run demo:status # 查看本机演示状态
npm run demo:stop   # 停止本机演示
```

### `.env.example`

提供生产或手工启动时所需环境变量的示例。实际使用时应复制为本地环境配置，并填入数据库、Redis、服务器节点和认证密钥等值。

### `docker-compose.yml`

提供本地 PostgreSQL、Redis 等基础设施的示例编排配置。`npm run demo` 不完全依赖该文件，而是由 `scripts/demo.cjs` 按需创建演示容器。

### `PLAN.md`、`README.md`、`需求文档.md`

- `README.md`：快速开始、运行方式、测试入口和项目边界。
- `PLAN.md`：架构、业务流程、接口、数据模型、安全要求和实施阶段。
- `需求文档.md`：用户角色、功能需求、权限模型、隔离要求和验收标准。

## 4. `apps/api`：管理 API 和任务调度

```text
apps/api/
├── src/
│   ├── main.ts
│   ├── store.ts
│   ├── security.ts
│   └── agents.ts
├── test/
│   └── security.test.cjs
├── package.json
└── tsconfig.json
```

### `apps/api/src/main.ts`

API 主程序，主要负责：

- 启动 NestJS HTTP 服务和 WebSocket 终端代理。
- 用户登录、登出和当前用户认证。
- 创建用户及角色管理。
- 查询和创建容器申请。
- 审批或驳回申请。
- 查询容器、启动、停止、重启、删除和查看日志。
- 为 Web Terminal 生成短时会话票据。
- 通过 BullMQ 将容器操作放入 Redis 队列。
- 周期性检查 Agent 节点和未完成任务，执行状态恢复。
- 生成供网关使用的应用路由信息。

API 默认使用 `/api` 路径；本机演示端口为 `3000`。

### `apps/api/src/store.ts`

PostgreSQL 访问层和数据库初始化逻辑：

- 创建数据库连接池。
- 提供事务封装。
- 启动时执行轻量数据库迁移。
- 定义核心表：`users`、`applications`、`containers`、`tasks`、`audit`。
- 提供审计日志写入函数。

用户表可以在数据库中查询：

```sql
SELECT id, username, role, active FROM users;
```

### `apps/api/src/security.ts`

安全公共函数：

- Zod 请求数据校验。
- 随机 Token 生成。
- Token 摘要计算。
- 使用 `scrypt` 哈希和校验密码。
- 用户资源归属权限判断。

### `apps/api/src/agents.ts`

Agent 节点客户端：

- 读取 `SERVERS_JSON` 中的节点配置。
- 使用 HMAC 签名调用 Agent 内部 API。
- 发送创建、查询和生命周期操作请求。
- 统一处理节点 URL、密钥环境变量和请求超时。

### `apps/api/test/security.test.cjs`

测试密码哈希、Token 和权限相关安全逻辑。

## 5. `apps/agent`：Docker 节点代理

```text
apps/agent/
├── src/
│   ├── main.ts
│   └── policy.ts
├── test/
│   └── policy.test.cjs
├── package.json
└── tsconfig.json
```

### `apps/agent/src/main.ts`

运行在管理节点或 Docker 节点上的 Agent 服务，主要负责：

- 通过 Docker Socket 访问本机 Docker Engine。
- 校验 API 发来的 HMAC 请求签名、时间戳和 nonce。
- 创建、查询、启动、停止、重启和删除用户容器。
- 创建和复用用户数据卷、网络及资源限制。
- 设置非 root 用户、只读根文件系统、能力丢弃和进程数限制。
- 查询 Docker 节点资源和容器日志。
- 通过 WebSocket 为用户提供容器内 `/bin/sh` 终端。
- 定时停止已经过期的容器。

生产环境要求配置 TLS 证书；本机演示使用本地 HTTP 通信和回环地址。

### `apps/agent/src/policy.ts`

Agent 的策略和校验逻辑：

- 校验创建容器的参数范围。
- 校验 HMAC 签名。
- 生成 Docker 容器 HostConfig。
- 设置 CPU、内存、磁盘、网络、卷、端口和安全选项。

### `apps/agent/test/policy.test.cjs`

测试创建参数校验、签名校验和 Docker 安全配置。

## 6. `apps/web`：前端界面

```text
apps/web/
├── src/
│   ├── App.vue
│   ├── main.ts
│   └── style.css
├── index.html
├── vite.config.ts
├── package.json
└── tsconfig.json
```

### `apps/web/src/App.vue`

当前前端的主要页面和交互集中在该文件：

- 登录和退出。
- 当前用户信息展示。
- 容器申请表单。
- 申请记录和审批中心。
- 容器状态、启动、停止、重启、删除和日志查看。
- 管理员创建账号。
- 服务器状态查看。
- 审计日志查看。
- 使用 xterm 和 WebSocket 展示容器终端。

### `apps/web/src/main.ts`

创建 Vue 应用，挂载 `App.vue`，并加载全局样式。

### `apps/web/src/style.css`

定义平台界面布局、表单、卡片、按钮、状态标签和移动端适配样式。

### `apps/web/vite.config.ts`

定义 Vite 开发和构建配置，包括本地开发时前端到 API 的代理关系。

### `apps/web/index.html`

浏览器入口 HTML 文件。

## 7. `scripts`：运行和测试脚本

### `scripts/demo.cjs`

本机演示监督程序：

1. 预留本地控制端口 `35179`。
2. 检查本机 Docker context 和 Docker Engine。
3. 编译三个 workspace。
4. 创建或复用 PostgreSQL、Redis 演示容器。
5. 构建或复用 `deploy/images/Dockerfile` 定义的开发镜像。
6. 启动 Agent、API 和 Vite Web 服务。
7. 通过 `demo:status` 和 `demo:stop` 提供状态查询和停止能力。

本机演示端口：

| 服务 | 端口 |
| --- | ---: |
| Web | 5173 |
| API | 3000 |
| Agent | 3100 |
| PostgreSQL | 55433 |
| Redis | 56380 |
| 演示控制端口 | 35179 |

### `scripts/integration.cjs`

执行真实集成测试，连接本机 PostgreSQL、Redis 和 Docker，验证用户申请、审批、容器创建、权限限制和可选网关流程。

## 8. `deploy`：部署和镜像配置

```text
deploy/
├── images/Dockerfile
├── gateway.yaml.example
├── nginx.conf.example
├── traefik.yaml.example
├── lab-api.service.example
└── lab-agent.service.example
```

### `deploy/images/Dockerfile`

定义用户开发容器镜像：

- 基于 `node:22-bookworm-slim`。
- 安装 Git、Python、Python venv、pip、Java、procps 和 CA 证书。
- 创建 UID/GID 1000 的 `developer` 用户。
- 默认执行 `sleep infinity`，等待平台通过终端连接。

### 网关配置示例

- `gateway.yaml.example`：应用入口和网关配置示例。
- `nginx.conf.example`：反向代理配置示例。
- `traefik.yaml.example`：Traefik 动态路由或入口配置示例。

### systemd 服务示例

- `lab-api.service.example`：生产 API 服务单元示例。
- `lab-agent.service.example`：生产 Agent 服务单元示例。

## 10. 典型运行流程

### 本机启动

```text
npm run demo
  ├─ npm run build
  ├─ 启动 PostgreSQL / Redis
  ├─ 构建开发镜像
  ├─ 启动 Agent
  ├─ 启动 API
  └─ 启动 Web
```

### 用户创建容器

```text
用户登录 Web
  → API 创建 applications 申请记录
  → 审批人批准申请
  → API 创建 tasks 任务并放入 Redis 队列
  → API Worker 调用 Agent
  → Agent 通过 Docker 创建用户容器
  → API 更新 containers 状态
  → 用户在 Web 中进入终端
```

## 11. 修改文件时的建议

- 用户、申请、审批、任务和审计逻辑：优先查看 `apps/api/src/main.ts`、`store.ts`。
- 密码、Token、签名和权限：查看 `apps/api/src/security.ts`、`apps/agent/src/policy.ts`。
- Docker 容器安全边界：查看 `apps/agent/src/main.ts`、`policy.ts` 和 `deploy/images/Dockerfile`。
- 页面交互和终端：查看 `apps/web/src/App.vue`。
- 页面样式：查看 `apps/web/src/style.css`。
- 本机启动行为：查看 `scripts/demo.cjs` 和 `docs/本机演示启动.md`。
- 生产部署：查看 `docs/部署说明.md` 以及 `deploy/*.example`。

修改后通常执行：

```bash
npm run build
npm test
```
