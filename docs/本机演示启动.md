# 本机演示启动

这套脚本使用本机 Docker，服务器二无需补齐。不会连接学校服务器，也不使用学校宿主机密码。

## 启动

1. 打开 Docker Desktop，等待引擎就绪。
2. 在终端执行：

```bash
cd /Users/yuanyaowu/Desktop/geli
npm run demo
```

首次启动会检查或安装依赖、编译项目，启动 PostgreSQL/Redis，并构建 Node.js + Python + Java 开发镜像，可能需要几分钟。镜像未变化时后续启动复用现有镜像。

首次自动创建网站管理员：账号 `admin`，默认密码 `yywzy26233a3`，无需交互输入。可通过 `BOOTSTRAP_ADMIN_PASSWORD` 环境变量覆盖（至少12字符）。数据库只存储密码哈希；已有 `admin` 账号时沿用原密码，不会自动重置。该默认值仅用于本机演示，生产 API 没有默认密码。

看到“演示启动成功”后，浏览器打开 **http://127.0.0.1:5173**，使用 `admin` 和上述默认密码（或自定义密码）登录。不要改用 localhost，以免终端来源校验不一致。

启动脚本前台运行，保持该终端打开。仅接受本机 Unix Socket Docker context，拒绝远程 Docker。

## 演示顺序

1. 管理员进入“创建账号”，创建普通用户 `student-a`。
2. 无痕窗口访问同一网站，使用普通用户登录。
3. 申请 `lab-dev` 镜像，资源建议 1 CPU、512 MB 内存、1 GB 磁盘、1 小时，应用端口 8080。
4. 管理员在“申请记录”中点击“通过并创建”。
5. 等待约10～30秒，普通用户在“我的容器”看到 `RUNNING`。
6. 点击“进入终端”，执行：

```bash
id
pwd
node --version
python3 --version
java -version
ps
```

用户工作目录为 `/home/developer`，以非 root 用户运行。可以使用项目内 npm 依赖或 Python venv，不提供 sudo。

## 状态与停止

另开终端，在同一项目目录执行：

```bash
npm run demo:status
npm run demo:stop
```

也可以在启动终端按 `Ctrl+C`。停止会关闭前端、API、Agent，以及本次启动的 PostgreSQL/Redis。原本已运行的数据库不会被脚本停止。

用户创建的容器不会自动停止，请在网站先点击“停止”。停止脚本不删除数据库容器、数据卷或用户容器，再次启动仍保留账号和申请记录。

## 演示限制

- 本机使用 tmpfs 容器工作盘，停止容器后文件可能丢失；不要保存重要代码。数据库记录与工作盘不同，数据库保留。
- 本次不自动启动域名网关，因此网站里的 `apps.example.test` 应用链接不可访问。审批、创建容器和真实终端可演示；真实域名发布请按《部署说明》配置。
- 数据库仅绑定回环地址，使用演示认证设置，不可直接用于学校生产环境。
- 默认预算为4 CPU、4096 MB内存、40 GB逻辑工作盘；实际运行受 Docker Desktop 分配资源约束。
- 占用端口：5173（Web）、3000（API）、3100（Agent）、55433（PostgreSQL）、56380（Redis）、35179（本地启停控制）。脚本不会终止占用这些端口的其他程序。

## 排错

服务日志位于 `.demo/logs/api.log`、`.demo/logs/agent.log`、`.demo/logs/web.log`，该目录已加入 Git 忽略。

- Docker 不可用：打开 Docker Desktop，确认当前 context 指向本机。
- 端口占用：先运行 `npm run demo:status`；已有演示用 `npm run demo:stop` 关闭，其他服务由你自行处理。
- 镜像下载或 npm 安装失败：检查本机网络、代理和 registry 配置，修复后重试。
- 密码不生效：已有账号不会因环境变量改变而重置密码，使用第一次设置的密码。
- 状态或停止命令提示“演示未运行”：只管理通过此脚本启动的实例，不会接管此前手工启动的服务。

部署到学校服务器时使用《部署说明》中的生产配置，不使用本机演示的数据库认证和临时卷。
